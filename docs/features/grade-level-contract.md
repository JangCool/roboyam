# 등급·레벨·도트 캐릭터 계약 (시안 확정 2026-11-11)

등급을 4단계에서 **경험치 → 레벨 → 등급** 구조로 바꾼다. 활동으로 쌓인 경험치가 레벨(Lv.1~, 끝 없음)을 올리고, 레벨 구간마다 등급(장인 계급 11단계)과 도트 캐릭터가 바뀐다. 글 목록·댓글에서는 등급 칩 대신 작은 도트 캐릭터만, 레벨은 프로필·내 정보에서만 보인다.
시안: 공유 노트 `roboyam-mockup.html`(③④⑥) — 사용자 「이대로 만들어」 2026-11-11. 기존 규칙은 `roles-contract.md` 2단계(등급) · `point-contract.md`.

## 1. 경험치·레벨
- **경험치(XP)** = 활동으로 **적립된** 포인트의 누적. 포인트를 쓰거나 소멸해도 줄지 않는다.
  - 더함: `POST` · `COMMENT` · `LIKE_BONUS` · `ATTENDANCE` · `ATTENDANCE_STREAK` · `POPULAR` · `POST_RESTORE`
  - 뺌: `POST_REVOKE` · `COMMENT_REVOKE` · `LIKE_BONUS_REVOKE` (0 아래로는 안 내려간다)
  - 넣지 않음: 운영 조정(`ADMIN_ADJUST`)·충전·충전 보너스·가입·이벤트 보상·작가 보상·사용·환불·상계·소멸 등 그 밖의 사유 전부.
  - 포인트 적립이 꺼진 게시판 활동은 경험치도 없다(적립 조건 — 최소 글자 수·간격·하루 한도 — 이 그대로 어뷰징을 막는다).
- 저장: `profiles.xp bigint NOT NULL DEFAULT 0`, `profiles.level int NOT NULL DEFAULT 1`. 포인트 원장 줄을 쓰는 같은 트랜잭션에서 증감하고 레벨을 다시 계산한다(세이브포인트 격리 규칙 그대로 — 실패해도 글쓰기를 깨지 않는다).
- **레벨 곡선**: 레벨 L(L≥2)에 필요한 누적 XP = `ceil(base × (L−1)^1.5)`, `base` 기본 10(`grade_settings.xp_curve_base`, 1~1000, 관리자 등급 설정에서 바꿈). 상한 없음(Lv.100 넘어도 계속). Java·SQL 이 같은 식을 쓴다.
- 마이그레이션 때 **기존 회원 XP 를 포인트 원장에서 다시 계산해 채우고** 레벨을 매긴다.

## 2. 등급 11단계 (장인 계급)
| 서열 | 키(기존 유지) | 이름 | 최소 레벨 | 가입 후 일수 | 도트 |
|---|---|---|---|---|---|
| 1 | SEEDLING | 새싹 | 1 | 0 | SPROUT |
| 2 | 새 키 | 견습 | 10 | 3 | BOLT |
| 3 | REGULAR | 정식 | 20 | 7 | ANTENNA |
| 4 | 새 키 | 숙련 | 30 | 14 | BATTERY |
| 5 | 새 키 | 정예 | 40 | 30 | GEAR |
| 6 | LOYAL | 고수 | 50 | 60 | HEART |
| 7 | 새 키 | 달인 | 60 | 90 | LIGHTNING |
| 8 | 새 키 | 명인 | 70 | 180 | STAR |
| 9 | VETERAN | 대가 | 80 | 365 | CROWN |
| 10 | 새 키 | 전설 | 90 | 540 | LEGEND |
| 11 | 새 키 | 신화 | 100 | 730 | MYTH |
- 등급 한도 10 → **11**(`ck_grades_level`·앱 검사·관리자 화면).
- 승급 조건 = **최소 레벨(`grades.min_level`, 새 칸) AND 가입 후 일수**(+ 기존 `min_activity` 는 남기되 새 기본값 0). 올리기만 한다(자동 강등 없음). 즉시 경로(경험치가 바뀔 때)와 일수 배치(`R__batch_15`) 둘 다 레벨 조건을 본다 — Java·SQL 이중 구현 규칙 그대로.
- 운영자가 수동으로 정한 등급: 지금 규칙 그대로(`manual_policy` — 수동 지정 회원은 옵션에 따라 자동 승급 계속/중지). 레벨은 수동 등급과 상관없이 계속 오른다.
- **기존 데이터 전환**(shared `V196`): **모든 사이트**를 위 11단계로 바꾼다(사용자 결정 2026-11-11 — 데이터를 지우지 않게). 기존 등급을 서열 순으로 보고, 시드 키 SEEDLING·REGULAR·LOYAL·VETERAN 은 서열 1·3·6·9 자리로, 운영자가 만든 키(`GRADE_n`)는 남은 자리 2·4·5·7·8·10·11 에 기존 서열 순서대로 넣는다(키 유지 — 이름·최소 레벨·일수·도트는 위 표로 덮어쓰고 `min_activity` = 0, 뱃지 색·아이콘은 그대로). 남은 자리와 지워진 시드 키의 자리는 새 키(`GRADE_<next_serial…>`)로 만든다. 운영자 키가 7개를 넘으면(시드를 지운 사이트만) 지워진 시드 자리까지 써서 자리 순으로 넣는다(키를 지우지 않으려는 예외). 등급 행은 지우지 않고 회원의 `grade_key` 도 그대로다. 등급 역할 이름은 새 이름을 따르고 없는 역할은 바로 아래 등급 역할의 권한을 복사해 만든다. 전환 뒤 소급 승급 한 번(올리기만, 이력 kind=AUTO).
- 설치 프리셋(`export-install-preset.mjs` 결과)·데모 데이터가 등급을 갖고 있으면 11단계로 맞춘다.

- **기존 회원 다시 매기기**(shared `V197`, 사용자 결정 2026-11-12): 전환 직후 **한 번만** 올리기·내리기를 모두 해서 회원 등급을 새 기준(최소 레벨 AND 가입 후 일수, 활동 조건 0 인 등급)에 맞춘다. 탈퇴하지 않은 회원 전부(정지·수동 지정 포함 — 다시 매긴 회원은 수동 표시를 끈다). 바뀐 회원마다 이력 kind=AUTO · reason_code `LEVEL_REGRADE`. 이 뒤로는 올리기만.

## 3. 도트 캐릭터 (`sprite`)
- 등급마다 `grades.sprite varchar(16)` — `SPROUT·BOLT·ANTENNA·BATTERY·GEAR·HEART·LIGHTNING·STAR·CROWN·LEGEND·MYTH` 중 하나. 관리자 등급 설정에서 등급마다 고른다(기본 = 서열 순). 기존 `badge_color`·`badge_icon` 은 남기되 공개 화면은 쓰지 않는다.
- 그림은 화면 코드(픽셀 지도 → SVG 사각형, `shape-rendering: crispEdges`, 한 칸 = 1 CSS px 정수배)로 그린다 — 이미지 파일·GIF 를 만들지 않는다. 픽셀 지도·색은 시안 파일의 것을 그대로 옮긴다.
  - **작은 판(12칸)**: 글 목록·댓글·글 보기 머리·피드·가젯 등 작성자 줄. 기본 12×12px(아바타 16px 보다 작다), 전설 16×14, 신화 20×14(오라·날개 포함).
  - **큰 판**: 공개 프로필·내 정보 — 작은 판 2배(닉네임 옆).
  - 구간 규칙: 눈빛 — 서열 1~5 흰색, 6~8 민트, 9~11 금빛 · 대가 = 작은 왕관, 전설 = 보석 큰 왕관 + 금빛 오라 + 반짝이, 신화 = 밝은 황금 몸 + 황금 날개 + 금빛 오라 + 보라 화면판.
  - **전설·신화는 움직인다**(4장면 220ms — 반짝이 깜빡·오라 숨쉬기·날개 펄럭) — 글 목록 포함 어디서나. `prefers-reduced-motion` 이면 첫 장면에서 멈춘다.
  - 접근성: `role="img"` + `aria-label`(등급 이름), `title` 로 이름.
- 작성자 줄(`PostAuthorLabel` — 글 목록·글 보기·댓글·피드·가젯): **등급을 보이지 않는다**(사용자 결정 2026-11-12 — 등급·레벨은 공개 프로필·내 정보에서만, 부품의 `grade` 기본 끔). 운영자·AI·사업자 뱃지는 그대로. 작은 판(12칸)은 부품에 남겨 둔다.
- 등급 이름이 보이던 다른 자리(데스크톱 계정 메뉴·쪽지·차단 목록 등 `GradeBadge`)는 도트 + 이름 글자.

## 4. 레벨 표시
- 글 목록·댓글·글 보기 머리: **등급 도트·레벨 숫자 모두 없음**.
- 공개 프로필 머리: 아바타는 그대로(72px·테두리), 닉네임 옆에 도트(2배) + 「등급 이름 · Lv.N」, 가입일 아래 경험치 막대(다음 레벨까지 %). 비공개 프로필이면 남에게는 레벨·막대를 숨긴다(등급 도트는 지금 등급 뱃지 규칙 그대로).
- 내 정보·`/me/grade`: 등급·레벨·XP·다음 레벨까지·다음 등급 조건(레벨·일수)을 보인다.

## 5. API
- `GET /api/site/info`: `grades: [{key, label, level(서열), sprite}]` — 화면이 작성자 `grade` 키로 도트·이름을 찾는다(작성자 DTO 는 지금처럼 `grade`·`gradeLabel` 만).
- 공개 프로필·`/api/me`(로그인 정보)·`/api/me/grade` 류: `level`, `xp`, `levelXp`(이 레벨 시작 XP), `nextLevelXp`(다음 레벨 XP) 추가. 비공개 프로필을 남이 볼 때는 레벨 칸 null.
- 관리자 등급 설정 `GET`·`PUT /api/admin/grades`: 등급마다 `minLevel`(1~10000)·`sprite`, 전역 `xpCurveBase`. 최대 11단계. 미리보기·소급 승급이 레벨 조건을 반영. 회원 상세에 `level`·`xp`.

## 미확정 / 가정
- 레벨 곡선 기본값(base 10)과 등급별 일수는 가정 — 운영하며 관리자 화면에서 고친다.
- 레벨업 알림·축하 효과는 이번 범위 밖.
