# 게시판 등급별 포인트 계약 (시안 확정 2026-11-17 · 구현 전)

**의도**: 모든 게시판이 같은 금액을 받던 글 적립을 게시판 등급(일반·정보·핵심 글)으로 나눈다. 쓰면 바로 주는 포인트는 작게, 가치가 확인됐을 때(추천 문턱·우수 글 선정) 주는 보너스는 크게 준다. 하루 인기글 보상도 실제로 지급한다.
**관련 계약**: `point-contract.md`(지금 적립 규칙 정본) · `member-title-contract.md`(우수 글 → 이달의 작가 후보) · `trial-group-contract.md`(구매 인증 보너스·체험단 사용기).
**시안**: 대화 시안 「1 / 3 · 포인트」(2026-11-17).

## 화면
- 관리자 `/points/policy`: 「글·댓글」 다음에 새 구획 **「게시판 등급별 지급」**. 지금 구획(출석·글·댓글·추천 보너스·하루 총 한도·핫딜·가입·운영 조정)은 그대로 둔다. 지금 글·댓글 금액은 「일반」 등급의 기본값이 된다.
- 관리자 `/points/policy` 「인기글 보상」: 「아직 적용되지 않아요」 딱지를 뗀다(실제 지급).
- 관리자 게시판 설정(`/boards/[slug]`·`/boards/defaults`): 포인트 칸 `pointMode` ON/OFF → **끔·일반·정보·핵심 글** 넷 중 하나. 고르면 그 등급의 금액·조건을 한 줄로 보인다.
- 관리자 글 보기 관리 메뉴: **「우수 글로 선정」**(포인트 + 홈·매거진 노출 후보), **「이달의 작가 후보에 넣기」**.
- 회원 글쓰기(`/write`): 정보·핵심 글 게시판이면 받을 포인트를 안내한다(「쓰면 50P, 추천 5개 받으면 150P 더, 우수 글로 뽑히면 500P」). 지금 글자 수·사진 수와 적립 조건을 같이 보인다.

## 등급별 칸 (기본값 · 범위는 기존 정책 칸과 같은 0~10,000)
| 칸 | 일반 | 정보 | 핵심 글 |
|---|---|---|---|
| 쓰면 바로(P) | 20 | 30 | 50 |
| 추천 문턱 보너스(P) | 10 | 50 | 150 |
| 우수 글 선정(P) | 0 | 100 | 500 |
| 최소 글자 수 | 50 | 100 | 500 |
| 사진 최소(장) | 0 | 0 | 1 |
| 보너스 보류(시간) | 0 | 24 | 24 |
- 추천 문턱은 지금 `likeBonusThreshold`(인정된 추천 규칙 그대로)를 함께 쓴다.
- 기본 배정: 일반 = 그 밖의 게시판, 정보 = 뉴스·핫딜, 핵심 글 = 사용기·팁·강좌.

## 규칙
- **쓰면 바로** 받는 포인트만 하루 총 한도(`dailyTotalCap`)에 든다. 추천 문턱 보너스·우수 글 선정·인기글 보상은 한도 밖이다.
- **보너스 보류**: 추천 문턱 보너스와 우수 글 보상은 보류 시간이 지난 뒤 확정한다. 그 사이 글이 지워지거나 신고로 숨겨지면 주지 않는다(지금은 숨김 회수가 없어서 보류로 막는다).
- 정보 등급: **같은 출처 링크는 한 번만 적립**(스위치, 기본 켬).
- AI 회원·운영팀 계정은 적립 안 함(스위치, 기본 켬).
- 기존 적립 조건(작성 간격·최소 글자 수 적용 스위치·내 글 댓글 제외·같은 글 댓글 1회)은 그대로 둔다. 「최소 글자 수」는 게시판 등급의 값을 쓴다.
- 인기글 보상: 매일 0시(한국 시간)에 전날 인기글 상위 `popularRewardTopN` 개에 `popularRewardPoints` 씩. 원장 사유 `POPULAR`(이미 있음), admin 배치.
- 우수 글 선정은 글마다 한 번(원장 유일). 운영자가 선정을 취소하면 보류 중일 땐 지급 취소, 확정 뒤면 회수하지 않는다. 글쓴이가 확정 뒤 글을 지우면 회수한다(추천 보너스와 같은 규칙).

## 원장 사유 (결정 2026-11-17)
- 추천 문턱 보너스: 기존 **`LIKE_BONUS`** · `LIKE_BONUS_REVOKE` 그대로. 금액만 게시판 등급에서 읽는다(새 사유 없음).
- 우수 글 선정: 새 **`POST_FEATURED`**(EARN, 대상 = 글 `POST`, 원장 유일로 글마다 한 번) · 새 **`POST_FEATURED_REVOKE`**(REVOKE, 본인 삭제 회수 — 받은 양만, 0P 바닥).
- 경험치(XP)에 넣는다: `POST_FEATURED` 더함 · `POST_FEATURED_REVOKE` 뺌(`grade-level-contract.md` 1절 목록에 더한다).
- `ck_point_ledger_reason`·`ck_point_ledger_reason_kind` CHECK 와 admin-web `PointReasonCode`·번들 `point.reason.*` 에 두 코드를 더한다.

## 보류 확정 방식 (결정 2026-11-17)
- 새 표 **`point_pending_grants`**: 회원 · 사유(`LIKE_BONUS`|`POST_FEATURED`) · 대상(`POST`/`COMMENT` + id) · 금액 · `release_at` · 상태 `PENDING`|`RELEASED`|`CANCELLED` · 취소 사유. 같은 (사유, 대상) 에 PENDING 은 하나(유일 색인).
- 보류 시간이 0 이면 지금처럼 바로 지급하고 표에 넣지 않는다.
- 보류 시작: 추천 문턱을 채운 순간 / 운영자가 선정한 순간 → `release_at = 그때 + holdHours`. 금액은 **그 순간의 정책값**으로 고정한다.
- 취소: 글·댓글 삭제(본인·운영자), 신고 숨김, 운영자 선정 취소가 일어나는 **같은 트랜잭션**에서 PENDING → CANCELLED.
- 확정: **admin 서버 5분 배치**가 `release_at` 지난 PENDING 을 `FOR UPDATE SKIP LOCKED` 로 집어 기존 `PointService` 지급 한 길로 넘기고 RELEASED 로 바꾼다. pg_cron SQL 이 아니라 admin 인 이유 = 지급이 묶음·미회수 상계·경험치·등급 승급까지 이어지는 자바 로직이라 SQL 로 두 번 만들지 않으려고(배치 규칙상 admin 허용). 원장 유일 키가 있어 두 번 돌아도 한 번만 지급된다.
- 확정 때 다시 본다: 회원이 정상(ACTIVE)이 아니거나 포인트 동결 중이면 지급하지 않고 CANCELLED(사유 남김). 글이 그새 사라졌으면 CANCELLED.
- 회원 `/me/points`: 「확정 대기」 줄로 보인다(+150P · 11월 18일 14:00 확정 예정). 관리자 회원 상세 포인트 구획에도 대기 목록.

## 권한
- 등급 칸 저장 = 기존 `point.settings`. 게시판 등급 배정 = 기존 `board.settings`.
- 우수 글 선정 = 새 권한 후보 `post.feature`(운영자). 게시판 매니저에게 줄지는 구현 때 정한다(권장: 운영자만).

## API 후보
- `GET/PUT /api/admin/settings/points` 에 `boardTiers: { NORMAL|INFO|CORE: { postPoints, likeBonusPoints, featuredPoints, minLength, minImages, holdHours } }`, `infoSourceOnce`, `excludeAiAndOps` 추가.
- 게시판 정책 `pointMode` 값 확장: `OFF|NORMAL|INFO|CORE`(기존 `ON` → `NORMAL` 전환).
- `POST /api/admin/posts/{id}/feature`·`DELETE`(우수 글 선정·취소).
- 회원 글쓰기 화면용: 게시판 정보 응답에 그 게시판의 등급 금액·조건.
- 회원 확정 대기: `GET /api/me/points/pending` → `{ items, freeze: { until } | null }`. 포인트 동결 중이면 「확정 대기」 구획에 「동결 중에 확정 시각이 오면 받지 못해요」 안내(화면 목업 때 더함 2026-11-17).
