# 운영 결제·환불·배송 조회 시험 기록 (2026-11-25)

운영(irobit.kr)에서 포트원 **시험 채널**(KG이니시스 V2)로 광고·공동구매 결제와 환불, 스마트택배 배송 조회를 실제로 돌려 본 기록이다. 로컬에서 볼 수 없던 **포트원 웹훅**(도메인 필요)과 **실제 택배 송장 조회**를 확인하는 것이 목적이었다.

- 카드 결제·본인인증·실제 송장 입력은 사용자가, 나머지(신청·승인·주문서·관리자 처리·DB/로그 확인)는 에이전트가 했다.
- 시험 데이터는 같은 날 모두 지웠다(백업 `/var/backups/irobit/irobit-before-testclean-20261125-0542.dump`). 운영 주체는 「개인」으로 되돌리고 판매는 껐다.
- 단계마다 `payment_orders`·`payment_events`·`payment_webhook_logs`·`payment_cancels`·`reconciliation_issues` 와 세 서버 ERROR 로그를 확인했다. 끝까지 **대사 이상 0건, 서버 오류 0건**.

## 시험 준비 (운영 DB·화면, 모두 시험 값)

- 운영 주체: 개인사업자(상호 「아이로빗(시험)」, 사업자등록번호 `123-45-67891` — 검증 공식을 통과하는 시험 번호, 통신판매업 시험 번호). DB 로 직접 바꿔서 감사 기록 없음.
- 사업자 회원: 회원 계정으로 `/business/apply` 신청(시험용 등록증 PDF) → 국세청 키가 없어 「조회 불가 상태로 승인」(사유 필수).
- 포트원: 웹훅 `https://irobit.kr/api/payments/webhooks/portone`, 버전 `2024-04-25`, **테스트 모드**에 등록하고 관리자 포트원 설정의 Webhook Secret 을 테스트 값으로 바꿈.
- 공동구매: 판매 켬, 배송비 정책 STANDARD(배송비 3,000원 · 5만 원 이상 무료 · 반품 3,000원 편도), 시험 상품(정상가 12,000원) · 공구가 10,000원 선착순 즉시 발송.

- 공구 주문은 본인인증이 먼저 뜨고(사용자가 직접), 주문서 → KG이니시스 결제 창 순서. 수량 선점 → 확정 → 취소 이동과 판매 수량이 맞게 바뀌었다.
- 모든 단계에서 **화면의 환불 예정액 = 서버 계산 = 실제 포트원 취소 금액**이었다.
- 하자·오배송 줄은 처리 방법에 「다시 판매」가 나오지 않는다(폐기·공급처 반송·보관만). 단순 변심 + 모집 중인 공구일 때만 다시 판매로 수량이 돌아온다.
- 나눠서 반품하면 반품비가 회수마다 붙는다(한 번에 2개 반품이면 17,000원). 정책상 맞다 — 결정 43은 처음 배송비 처리만 같게 한다.

## 배송 조회 (스마트택배 조회 API, 계약 결정 90)

| 주문 | 시험 | 결과 |
|---|---|---|
| G2026112500005 | 사용자가 결제 → 관리자에서 발송 처리(택배사 한진, **실제 송장 번호** — 사용자가 직접 입력) → 주문 서랍 **[지금 조회]** | ✅ 택배사 단계 **배송중**, 이력 6줄(시각·위치)이 관리자 서랍과 회원 주문 상세에 보임 |
| 〃 | 배송완료 | 사용자가 운영자로 직접 [배송완료] 처리 — 택배사 완료 시각으로 자동 배송완료되는 길은 운영에서 보지 못함(서버 시험 `GroupBuyParcelTrackingTest` 로만 확인) |

- API 키는 관리자 설정 › 커머스 › 배송 조회에 사용자가 직접 넣음(암호문 저장). 이용권은 체험 100회(11-25 ~ 12-25).
- 요청은 `POST https://info.sweettracker.co.kr/api/v1/trackingInfo` JSON 만 쓴다(GET 은 2026-12-01 14:00 종료, TLS 1.2 이상 — 2026-12-21 부터 1.0/1.1 막힘).
- 시험하며 고침: 회원 화면 진행 표시를 네 칸에서 **세 칸(집화 → 배송중 → 배송완료)** 으로 줄였다. 배송출발(5)·지점 도착(4)은 배송중에 묶고 이력 줄에는 그대로 보인다(사용자 — 「배송중 다음에 배송완료」).
- 시험 주소 대신 실제 송장을 썼기 때문에, 화면과 문서에는 송장 번호를 남기지 않는다. 받는 분 이름·주소는 스마트택배가 더 이상 돌려주지 않는다.

## 시험 중 겪은 문제와 처리

- **웹훅이 오지 않음**: 포트원 콘솔의 웹훅을 **실연동** 쪽에 등록했었다. 테스트 모드로 옮기고 새 Webhook Secret 을 관리자에 저장하기 전까지는 서명 불일치(400)로 거절됐다. 저장 뒤 정상.
- **광고 1 취소 웹훅만 안 옴**: 테스트 모드 웹훅을 설정하기 전에 만든 결제라 그 결제에 웹훅이 묶이지 않은 것으로 보인다. 취소는 서버가 직접 요청해서 상태는 맞았다.
- **시작 전 환불은 부분 승인이 안 됨**: 계약대로 시작 전 요청은 전액 자동 환불이라, 부분 취소는 진행 중 중단(광고 3)으로 시험했다.
- 시험하며 고쳐 배포한 것: 공구 상세 정상가 기준 문구 키(`PREVIOUS_SALE`), 반품 완료 창을 처리 방법 선택 상자로, 광고 승인 창 강조 색, 주문 일괄 버튼 색·아이콘, 회원 배송 진행 세 칸.

## 실제 판매 전에 할 일

- 포트원 Webhook Secret 을 **실연동(live) 값**으로 되돌린다(관리자에는 비밀값이 하나만 저장된다). 콘솔 테스트 모드 웹훅은 남겨도 된다.
- 운영 주체를 실제 사업자 값으로 다시 넣고(개인사업자 단계 + 통신판매업 신고번호), 약관 새 판을 게시한 뒤 판매를 켠다.
- 스마트택배 이용권을 사고 **자동 조회**를 켠다(지금은 꺼 둠). 필요하면 「N일 뒤 자동 배송완료」도 정한다(기본 꺼짐).
- 아직 운영에서 보지 않은 것: 일반 카드(간편결제 아님) 결제, 포트원 콘솔에서 직접 한 취소의 대사 이상 잡기, 택배사 완료로 자동 배송완료, 에스크로·가맹점 취소 한도.
- R2 에 남은 시험 반품 사진(`groupbuy/request/202611/` 2장)은 사용자가 Cloudflare 대시보드에서 지우기로 함.
