# 홈 첫 방문 JS·CSS 크기 — 원인과 줄이는 방법 (2026-11-17 밤 측정)

질문: 「11-12 에 254KB 였는데 지금 480KB — 기능이 늘었다고 이렇게 차이 나나?」

## 1. 결론 먼저

- **두 숫자는 잣대가 달랐다.** 254KB 는 「처음 받는 엔트리 + 엔트리가 바로 가져오는 조각」(엔트리 정적 닫힘)이고, 480KB 는 「홈을 열고 7초 동안 받은 JS·CSS 전부(가젯·셸 부품 포함)」다. QA 기록에 「두 배」라고 쓴 것은 제 잘못이다.
- **같은 잣대로 다시 재면 오히려 줄었다.** 11-12 화면 코드(be1788de)를 지금 서버·지금 데이터로 띄워 같은 방법으로 재면 홈 534KB, 오늘 develop 은 480KB(−10%). 엔트리 정적 닫힘은 248KB → 245KB 로 거의 같다.
- 운영은 Cloudflare 가 brotli 로 내리므로 실제 전송은 gzip 보다 약 14% 작다(오늘 develop 홈 **brotli 412KB**).
- 남은 480KB 는 큰 덩어리 하나가 아니라 **프레임워크(Vue·Nuxt·i18n·PrimeVue 약 190KB) + 앱 코드 여러 곳에 고르게** 퍼져 있다. 실험해 보니 한 번에 크게 주는 방법은 없고, 아래 몇 가지를 모으면 **약 45~60KB(10~12%)** 를 더 줄일 수 있다고 본다.

## 2. 같은 잣대로 잰 값

측정: 운영 빌드(`pnpm generate`)를 오늘 api jar 로 임시 포트 8911 에 띄우고, Chrome(로그인 상태) 으로 홈을 연 뒤 7초 동안 받은 `/_nuxt/*.js·css` 를 파일마다 압축해 더했다(전송과 같은 방식).

| 화면 코드 | 홈이 받는 파일 | gzip | brotli | 엔트리 정적 닫힘(gzip) |
|---|---|---|---|---|
| 11-12 be1788de(254KB 라고 적었던 때) | 224개 | 534KB | 459KB | 248KB |
| 오늘 develop e68bcd3b | 207개 | **480KB** | **412KB** | 245KB |

## 3. 480KB 는 어디에 쓰이나 (실제 전송 기준 나눔)

조각마다 실제 gzip 을 재고, 조각 안 모듈의 원본 크기 비율로 나눴다(E1·E4 실험을 얹은 470KB 빌드 기준).

| 묶음 | gzip | 비율 | 메모 |
|---|---|---|---|
| PrimeVue 부품·코어·스타일 | 75KB | 16% | Menu·Dialog·Drawer·Popover·Tooltip·Button 등, 상단 바 팝업이 큰 몫 |
| 앱 utils | 69KB | 15% | `class UtilX { static … }` 규약 — 상수 하나만 써도 클래스 통째(아래 E12) |
| Vue·라우터 | 44KB | 9% | 뺄 수 없음 |
| Nuxt·unhead·경로표 | 40KB | 9% | 뺄 수 없음(경로표 약 200쪽) |
| 문구 | 36KB | 8% | 오늘 맨 위 키 단위로 줄인 뒤 |
| 앱 셸(상단 바·메뉴·알림) | 33KB | 7% | |
| 앱 홈·가젯 | 32KB | 7% | |
| CSS 파일 | 32KB | 7% | Tailwind+main.css 28KB, primeicons 아이콘 규칙 2.5KB |
| 앱 그 밖 부품(글 줄·광고·배지) | 31KB | 7% | |
| 앱 composables | 30KB | 6% | |
| i18n 엔진 | 26KB | 6% | 이 중 메시지 컴파일러 약 7KB(E3) |
| PrimeVue 테마 토큰 | 11KB | 2% | |
| PrimeUI 라이선스 확인 | 4KB | 1% | 유료 라이선스라 뺄 수 없음 |

## 4. 해 본 실험 (실제로 빌드해 재 봄 — 브랜치 `exp/bundle-size`, 병합 안 함)

| | 방법 | 결과 | 판단 |
|---|---|---|---|
| E1 | 문구를 맨 위 키가 아니라 **실제 쓰는 키 경로**까지 잘게(`business.home.title` → 그 한 줄만) | 480 → 475KB(−5KB), 키 글자 노출 없음 | 작지만 위험 낮음 — 넣어도 됨 |
| E4 | PrimeVue Aura 테마 토큰을 **쓰는 부품 약 30개만** 담은 프리셋 | 475 → 470KB(−5KB), 버튼 모양 그대로 | 작음. 새 부품을 쓸 때 목록에 더해야 하는 관리 부담 |
| E5 | 작은 조각(165개) **합치기**(rolldown `experimentalInlineCommonChunks`) | 파일 207 → 111개, 그러나 **475 → 516KB(+41KB)** — 공통 코드가 여러 곳에 복사됨 | 하지 않는다(요청 수만 줄고 바이트는 늘어난다) |

## 5. 아직 안 해 본 것 — 추정 효과 (모듈 크기로 계산)

| | 방법 | 추정 | 위험·비용 |
|---|---|---|---|
| E2 | 상단 바 팝업을 **열 때 받기** — 사용자 메뉴(Menu)·글쓰기 메뉴(TieredMenu)·메뉴 서랍(Drawer)·확인 창(Dialog)·알림 패널·메뉴 서랍 내용 | **20~30KB** | 중간. 첫 클릭 때 아주 잠깐 늦게 열림(조각 하나 받는 시간). Popover·Dialog 는 본문(AI 배지·말줄임·시트)도 써서 일부만 빠진다 |
| E12 | utils 규약 바꾸기 — `class UtilX { static }` → 함수·상수 이름 내보내기(번들러가 안 쓰는 함수를 뺄 수 있게) | **15~30KB**(홈 utils 69KB 중) | 큼. 가이드 `utils.md` 규약 변경 + 많은 파일 수정. 단계적으로(셸이 쓰는 utils 부터) 가능 |
| E3 | 문구를 빌드 때 미리 해석해 두고 vue-i18n 실행용(메시지 컴파일러 없는) 판 쓰기 | **약 7KB** + 문구 처리 CPU 감소 | 중간. 빌드 모듈이 문구를 AST 로 바꿔 실어야 함 |
| E11 | 관리자 미리보기 코드(`util-admin-preview` 등)를 미리보기 창일 때만 받기 | 약 3~5KB | 낮음 |
| E7 | 운영 번들에 들어간 vue-router devtools 조각 빼기 | 약 3~4KB | 낮음(설정 한 줄 확인) |
| — | 화면 아래쪽 가젯 코드를 보일 때 받기 | 10~20KB | 11-14 결정(스플래시는 다 그려진 뒤 걷힘)과 부딪힘 — 권하지 않음 |

**합치면**: E1·E4·E2·E3·E11·E7 → 약 **45~55KB**(480 → 약 425KB gzip, brotli 약 365KB). E12 까지 하면 400KB 안팎.
254KB 근처(홈 전체 기준)는 Vue·Nuxt·i18n·PrimeVue 만 약 190KB 라 현실적이지 않다.

## 6. 권하는 순서

1. **E2 상단 바 팝업 열 때 받기** — 효과가 가장 크고 화면 동작 변화가 적다.
2. **E1 + E11 + E7** — 작지만 위험 낮음, 한 번에.
3. **E3 문구 미리 해석** — 빌드 모듈 손질(한 곳)로 끝난다.
4. **E12 utils 규약** — 효과는 크지만 규약 결정이 필요(사용자 결정 사항).
5. E4 는 부품 목록 관리 부담 대비 효과(5KB)가 작아 보류, E5 는 하지 않는다.

## 7. 적용 결과

- **E2 적용(2026-11-17)** — 상단 바 사용자 메뉴·공지 띠 닫기 메뉴(`LazyMenu` + `useLazyPopup`)·알림 패널·하단 탭 메뉴 서랍·확인 창·사이트 팝업 대화상자를 처음 열 때 받기. 같은 잣대로 **480 → 457KB(−23KB), 파일 207 → 196개**. 사용자 메뉴(단추 바로 아래)·알림 패널(종 아래)·공지 띠 닫기 메뉴·로그아웃 확인 창(취소)·메뉴 서랍 열고 닫기를 Chrome 으로 확인, user-web 타입 검사 통과. 두 번째 클릭으로 메뉴가 안 닫히는 것은 바꾸기 전(3100)도 같다(코드로 누른 클릭의 특성).

- **E1·E11 적용(2026-11-17)** — 문구를 코드에 적힌 키 경로 단위로 싣기(E1), 관리자 미리보기의 메시지 읽기·홈 구성 덮기를 `util-admin-preview-apply.ts` 로 떼어 미리보기 창에서만 받기(E11, 플러그인 03 이 받아 `useAdminPreview().apply` 에 둔다). **457 → 450KB**, 공개 홈은 미리보기 코드를 받지 않음 확인. 관리자 테마 화면 미리보기(테마 바꾸기 → 다음식 배치로 바뀜, 편집 모드 가젯 테두리)를 개발 서버에서 확인, 타입 검사 통과.
- **E7 해당 없음** — vue-router 5 의 `devtools-*.js` 는 이름과 달리 주소 해석 등 라우터 핵심 함수가 든 공용 모듈이었다(뺄 것이 없다).
- **E3 하지 않음** — 한국어 문구 전체를 미리 해석(AST)하면 gzip 101KB → 119KB(+18%). 홈 문구로 치면 약 +6.5KB 라 메시지 컴파일러를 빼는 이득(약 7KB)과 비기고, 문구가 많은 화면은 손해다.
- **E4 보류** — 테마 토큰을 쓰는 부품만 담으면 −5KB 지만, 새 PrimeVue 부품을 쓸 때마다 목록에 더해야 하고 빠뜨리면 모양이 깨진다.
- **E12 결정 필요** — utils 를 클래스(`static`)에서 함수·상수 이름 내보내기로 바꾸기(추정 15~30KB). 가이드 `utils.md` 규약을 바꾸는 일이라 사용자 결정 뒤에.

**지금까지**: 같은 잣대(홈 첫 방문 JS·CSS gzip) 480KB → **450KB(−30KB, −6%)**, 파일 207 → 197개.
