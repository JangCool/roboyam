# Frontend i18n Guide (`i18n.md`)

화면 문구를 한국어·영어로 보여 준다. 공유 레이어 `@roboyam/i18n`(`@nuxtjs/i18n`)이 설정·공통 문구(`common`)·`useLanguage`·`useTranslate`·`useLocalizedName`·`UtilI18n` 을 제공한다. 앱은 `extends` 에 명시한다.

## 1. 구조
* 언어는 `ko`(기본·폴백) · `en`. `strategy:'no_prefix'`(주소로 가르지 않음), `detectBrowserLanguage:false`(브라우저를 따르지 않음). **언어는 표시 값**(`DisplayValues.language` — 사용자 → 사이트 기본값 → `ko`)에서 오며, `useDisplay().setDisplay(...)` 가 vue-i18n 과 PrimeVue 로캘을 함께 바꾼다.
* 문구 파일은 업무별 `i18n/locales/{ko,en}/{업무}.ts` 다. 앱은 **앱 루트** `i18n/`(`app/` 안이 아니다), 레이어는 레이어 루트 `i18n/` 에 둔다. **파일 이름이 업무 이름**(키의 첫 마디)이고 목록에 따로 등록하지 않는다 — 새 업무는 두 언어 파일만 만든다(한쪽 언어에만 있으면 그 언어에서 한국어로 보인다). 업무 이름은 앱과 레이어를 통틀어 하나여야 한다(겹치면 빌드가 멈춘다).
* ⚠ `i18n.config.ts` 는 Nitro 서버에서도 번들된다 — `import.meta.glob`·가상 모듈 같은 Vite 전용 것을 쓰면 서버 i18n 초기화가 조용히 실패해 모든 요청이 500 이 된다(타입 검사로 안 잡힌다).
* **문구는 쓰는 화면이 가져간다**(2026-11-12 — 첫 화면은 첫 화면이 쓰는 업무만). `@roboyam/i18n` 의 빌드 모듈(`build/business-messages.ts`)이 코드에서 따옴표·백틱 바로 뒤의 `업무.` 꼴 글자를 보고 그 모듈 조각에 그 업무의 한국어 문구를 싣는다. 그래서 **키는 코드에 글자 그대로 적는다** — `t('account.title')`, 상수 `labelKey: 'menu.home'`, 앞마디를 쓴 템플릿 문자열(`grade.level${n}` 을 백틱으로) 모두 잡힌다. 업무 이름까지 변수로 조립하면(`${biz}.title`) 못 찾는다 — 그런 키와 서버가 내려준 키(`nameKey` 등)는 처음 그릴 때 잠깐 키가 보였다가 안전망(`missing` 처리기가 그 업무를 받는다)으로 채워진다.
* 문구를 `i18n.config.ts` 의 `messages` 나 모듈 로캘 파일(`locales[].file`)로 다시 넣지 않는다 — 모든 화면 문구가 첫 화면에 실린다. `i18n.config.ts` 는 `@roboyam/i18n` 의 언어 기본값(`legacy`·`locale`·`fallbackLocale`)만이다. 언어를 바꿀 때는 `useLanguage().setLanguage` 를 쓴다(등록된 업무의 그 언어 문구를 받은 뒤 바꾼다 — `locale.value` 를 직접 바꾸면 받지 않은 언어의 키가 보인다).

## 2. 키와 문구
* 키는 `업무.무엇` 두 마디(`t('common.save')`, `t('site.nameLabel')`). **화면 이름을 키에 넣지 않는다.** 업무 없는 말(저장·취소·전체)은 `common` 이고, 같은 말이 두 업무 파일에 반복되면 `common` 으로 올린다.
* 영어는 `ko` 와 같은 키·같은 차례로 쓴다(자연스럽고 짧은 UI 용어). `missingWarn` 을 끄지 않는다. 새 화면은 처음부터 i18n 키를 쓴다.
* 문구 안 `@` 와 `|` 는 `{'@'}` · `{'|'}` 로 이스케이프한다(안 하면 "Invalid linked format" 으로 컴파일이 죽는다). `<…>` 꼴은 HTML 로 보여 경고하므로 따옴표로 감싼다. PrimeVue `{totalRecords}` 는 `t('common.totalCount', { count: '{totalRecords}' })` 로 넘긴다.

## 3. 사용
* 컴포넌트: `const { t } = useI18n()` 를 setup 맨 위에 둔다. 컴포저블·플러그인·미들웨어: `const t = useTranslate()`(`await` 뒤에도 안전). `await` 뒤·콜백 안 `useI18n()` 호출과 `defineProps` 기본값의 `t()` 는 안 된다 → `composables.md` Nuxt 문맥 함정.
* 상수 문구는 유틸에 두지 않고 컴포넌트가 `t('업무.키')` 를 부른다. **계산이 낀 문구**(분기·자리표시자·조합)만 `utils/util-<업무>-messages.ts` 에 두고 **`t` 를 첫 인자로** 받는다(타입 `Translate`, `#layers/i18n/utils/util-i18n`). 서로 호출하는 유틸은 `t` 를 그대로 넘기고, 컴포넌트는 템플릿·`computed` 에서 `UtilXxxMessages.fn(t, …)` 를 불러 언어 변경에 다시 계산되게 한다.
* 분기는 문구가 아니라 코드로 한다. 서버 오류 `code` → 문구 맵은 키(`error.INVALID_CREDENTIALS`)로 둔다.
* 한국어 조사(`를/을`·`는/은`) 계산은 한국어 전용이다. 문장 전체를 키로 두고 칸마다 문장 키를 둔다.
* ⚠ 모듈 최상위 상수·`static readonly` 에 번역 결과를 굳히지 않는다(언어를 바꿔도 다시 계산되지 않는다). 함수나 `computed` 로 하고 옵션 목록은 `computed(() => keys.map((k) => ({ label: t(k) })))` 로 만든다. `t` 를 모듈 변수에 저장해 다른 곳에서 쓰지 않는다.

```ts
// utils/util-site-messages.ts
static problem(t: Translate, field: SiteField): string { return t('site.nameRequired'); }
// i18n/locales/ko/site.ts → nameRequired: '사이트 이름을 입력해 주세요.'   en/site.ts → nameRequired: 'Enter a site name.'
```

## 4. 동적 이름 (게시판·메뉴 등 운영자가 정하는 값)
번역 파일에 둘 수 없으므로 항목이 기본 이름 `name`(메뉴 노드는 `label`)과 선택 영문명 `nameEn` 을 가진다. 언어가 `en` 이고 `nameEn` 이 있으면 그것을, 아니면 기본 이름을 보인다. 화면은 `const { localizedName } = useLocalizedName()` → `localizedName(node.label, node.nameEn)` 만 쓴다(규칙은 `UtilI18n.localizedName` 한 곳). 서버는 `name_en`(NULL 허용), 관리 화면에는 영문명 입력칸을 둔다.

## 5. 서버가 내려 주는 문구
`useApiClient` 가 모든 요청에 `Accept-Language: ko|en`(요청 시점의 화면 언어)을 붙이고 서버가 그 언어로 `message`·`fields` 문구를 준다. 화면이 `code` 로 자기 문구를 고르는 곳(`error.*`) 외에는 서버 `message` 를 그대로 쓴다(가공 금지 → `forms.md`). 서버 응답을 흉내 내는 목업(`*-mock.ts`)의 문구는 서버 몫이라 번역 키로 옮기지 않는다.

시각 글자(`UtilTime`)의 "어제"·"N분 전" 같은 말은 `vue-i18n` 이 아니라 표시 값의 `language` 로 고르는 단어표(`util-time-words.ts`)를 쓴다 → `layers.md`.
