# Frontend Form & Validation Guide (`forms.md`)

## 1. 역할 및 기본 원칙
* 폼은 데이터 누락 없이 정확히 바인딩하고, 서버 응답 오류는 가공하지 않고 그대로 보여 준다.
* 판정은 서버다. 화면 검사(`utils/util-<업무>.ts`)는 미리 알려 주는 용도이며 서버와 같은 규칙을 쓴다(서버 규칙 이름은 `composables.md` 타입 절 참고).

---

## 2. 주요 업무 및 규약

### 2-1. 필드와 데이터
* 수정할 수 없지만 서버 값이 폼에 포함돼야 하는 칸은 `readonly` 를 쓴다. `disabled` 는 제출에서 빠진다.
* 늦게 도착하는 서버 데이터로 만드는 폼은 `:key` 를 걸어 데이터가 오면 폼이 재구성되게 한다.
* 비밀번호·토큰·시크릿은 그 화면 메모리에만 둔다. `localStorage`·`sessionStorage`·URL·`useState`·로그·토스트에 남기지 않고 제출이 끝나면 비운다.

### 2-2. 서버 오류
* 서버 `message` 를 다른 문구로 덮어쓰지 않는다. `ApiError`(`useApiClient`)의 `message` 가 서버 문구이고, `UtilBoardMessages.of(t, e)` 처럼 메시지 유틸이 `ApiError` 가 아닌 오류(네트워크 등)까지 보일 한 줄로 바꾼다.
* 분기는 문구가 아니라 `ApiError.code` 로 한다(일부러 뭉뚱그린 문구를 화면이 갈라 쓰면 의도가 깨진다).
* 입력 오류(`400 VALIDATION`)의 `fields` 키는 점·대괄호 경로(`root.email`, `social.providers[0].clientId`)다. 해당 입력칸 아래에 붙이고, 칸에 붙지 않는 것만 폼 위쪽에 모은다.
* 권한 때문에 못 보는 것(403)은 오류가 아니다. 요청 자체를 거르거나, 여러 요청은 `Promise.allSettled` 로 한쪽이 막혀도 나머지를 보여 준다.

### 2-3. 오류·결과를 어디에 보일까
| 언제 | 어디 |
|---|---|
| 폼 제출 실패 | 폼 안 `Message severity="error" variant="simple"` (또는 칸 아래) |
| 목록 한 줄 수정 실패 | 토스트, 사유(`detail`) 포함 8초 |
| 화면 전체 로드 실패 | `ErrorState`(다시 시도 포함) |
| 성공 | 토스트 3초 |

### 2-4. [저장]·[되돌리기]를 어디에 둘까 (관리자 설정 화면)
저장 단위가 정한다. community 프로젝트의 `SaveBar`/`StickySaveBar` 를 따른다.
| 저장 단위 | 위치 | 부품 |
|---|---|---|
| **구획마다 따로 저장**(구획이 자기 요청·자기 dirty 를 가진다) | 그 **구획 맨 아래**(구획 안 저장 줄) | `SaveBar` |
| **화면 하나로 한 번에 저장**(여러 구획·목록·옵션을 PUT 한 번에 보낸다) | **페이지 맨 아래, 창 아래에 떠 있는 줄**. 구획 안에 [저장]·[되돌리기]를 두지 않는다 | `StickySaveBar` |

* 구획이 여럿인데 저장이 하나인 화면에서 특정 구획 안에 [저장]을 두면 "그 구획만 저장된다"고 읽힌다. 저장 줄은 구획 밖, 모든 구획 아래(`<form>` 맨 끝)에 둔다.
* 떠 있는 줄(`StickySaveBar`)은 데스크톱(`md` 이상)에서 `sticky bottom-3 z-20` 로 창 아래에 붙고, 모바일은 고정하지 않고 맨 아래 일반 줄이다. 칸 목록이 길어 모바일에서도 저장 줄이 한참 아래인 화면만 모바일도 붙인다. `fixed` 가 아니라 `sticky` 로 두어 페이지 끝의 마지막 칸을 가리지 않게 한다.
* 줄의 모양: 왼쪽에 상태 글이 **늘 보인다**("변경한 값이 없어요" / "N개 칸을 바꿨어요" / 맞지 않는 칸이 있으면 " · 오류 N건"), 오른쪽에 [되돌리기](텍스트형)와 [저장]. 저장 실패 한 줄(칸에 붙지 않는 오류)은 이 줄 안에 선다. 칸마다의 오류 문구는 그 칸 아래에 따로 둔다.
* [저장]은 고친 값이 있을 때만, [되돌리기]도 고친 값이 있을 때만 켠다. 입력 오류·권한 없음은 [저장]만 막는다. 권한이 없으면 줄을 그리지 않고 읽기 전용 안내를 보인다.
* 저장하지 않은 변경이 있는데 다른 화면으로 가면 확인을 묻는다(`onBeforeRouteLeave`).
* 이 구분이 이미 맞는 화면: 「일반」(구획마다 저장 → 구획 안 저장 줄). 등급 설정은 목록·뱃지·옵션을 PUT 한 번으로 저장하므로 하단 떠 있는 줄이다.

## 3. 작성 예시
```vue
<form v-if="user" :key="user.id" @submit.prevent="save">
  <input :value="user.username" readonly />        <!-- 수정 불가지만 제출에 포함 -->
  <input v-model="form.email" />
  <small v-if="fieldErrors['email']">{{ fieldErrors['email'] }}</small>   <!-- ApiError.fields -->
  <Message v-if="formError" severity="error" variant="simple">{{ formError }}</Message>
</form>
```

## 4. 금지 사항 (Anti-Patterns)
1. ❌ 제출 값이 필요한 수정 불가 칸에 `disabled`
2. ❌ 서버 오류 문구를 가공해 다른 문구로 덮어쓰기, 문구 비교로 분기
3. ❌ 비밀번호·토큰·시크릿을 저장소·URL·로그·토스트에 남기기
4. ❌ 403 을 화면 오류로 올리기
5. ❌ 화면 하나로 저장하는데 [저장]·[되돌리기]를 특정 구획 안에 두기(하단 떠 있는 저장 줄에 둔다)
